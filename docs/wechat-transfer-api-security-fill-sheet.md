## 2. 找到真正要填写的接口 IP

微信“接口 IP”控制的是**后端主动请求微信时的公网来源 IP**。回调地址是微信访问后端的入口，两者方向不同。[微信接口安全说明](https://pay.wechatpay.cn/doc/v3/merchant/4013751010)

本项目优先按以下路径核对：

1. 打开云开发 CloudBase 控制台，选择你自己的云环境（your-cloud-env-id）。
2. 进入“云函数”，查找精确名称 pengyu-pay-fj7pei2f-demo-scfweb，核对它确实部署了当前支付代码。
3. 在函数“配置/编辑 → 网络配置”先确认是否使用 VPC 私网，再查看“公网访问”和“固定出口 IP”。如要启用固定出口，先核对本环境套餐与页面提示，再保存并等待更新完成。
4. 复制该页面显示的固定出口 IP，记录环境、函数名、取得日期；若显示多个出口，记录所有可能出站地址。
5. 微信支付商户平台 → 产品中心 → 运营工具 → 商家转账 → 前往功能 → 安全能力（或系统信息管理）→ 接口 IP → 添加。按实际字段逐条填写，不猜测逗号批量格式。此项由超级管理员或安全联系人配置。

CloudBase 云函数内置固定出口仅在公网访问开启时生效；同一命名空间开启该能力的函数共享相应出口。目标函数未启用 VPC 私网时，优先使用内置固定出口，无需另建 VPC/NAT；已启用 VPC 时，应先核实其公网网关、NAT 和路由，再确认真正生效的出口，不能仅抄一个开关旁的地址。[云函数网络配置](https://docs.cloudbase.net/cloud-function/function-configuration/config)

如果在云函数列表找不到目标，不要拿其他服务的 IP 代填。先核对真正的部署环境和名称。本地 cloudbaserc.json 中 HTTP 函数及云托管模板都叫 pay-common，环境还是占位符，与小程序配置不一致；该文件不能证明实际部署到了哪里。

只有确认支付代码实际运行在云托管时，才改查“云托管 → 环境设置 → 固定公网 IP”。云托管启用 VPC 时，公网流量需按其 VPC/NAT 路由出站，名单应填写实际 NAT 的 EIP，不能沿用另一套出口。[云托管固定公网 IP](https://docs.cloudbase.net/run/deploy/networking/staticip)

固定出口的套餐可用性按目标环境页面核实，不能承诺免费；自建 NAT 另有网关、CU 及公网网络费用。[NAT 计费](https://cloud.tencent.com/document/product/552/12954)

| 后台字段 / 核对项 | 应填内容 |
| --- | --- |
| 系统名称（如页面要求） | 可用“宿院集二手回收后端”，仅作识别；先核对当前产品对外名称 |
| 接口 IP | 待确认：上述实际支付资源显示的固定公网出口 IP |
| API 发起方式（如页面要求） | 开启与该业务对应的 API 调用；不等于代码已经启用转账 |
| 场景 | 已正式开通的二手回收 1010 |
| 金额和累计限额 | 正式设置页数值，含单笔、商户日/月、单用户日限制 |

不要填开发电脑 IP、127.0.0.1、内网地址、api.mch.weixin.qq.com 的服务器 IP、回调域名解析 IP 或任意测试 IP。部署迁移、停用后重开固定出口时重新核对名单；本地电脑不能假定获准直接调用正式转账。

## 3. 服务端运行配置：字段名区分大小写

以下左栏是**当前 config/config.js 实际读取的环境变量名**，用于部署后的支付函数配置；不是小程序前端配置。继续使用本商户有效的在用凭据，不因新增场景盲目重置。

| 服务端变量名 | 要填什么 / 如何确认 |
| --- | --- |
| appId | wx-your-appid |
| merchantId | your-merchant-id |
| merchantSerialNumber | 与请求签名私钥配套的商户 API 证书序列号 |
| privateKey | 对应商户 API 私钥，PEM；只放受保护服务端配置 |
| apiV3Key | 本商户 APIv3 密钥；用于通知解密，只放服务端 |
| wxPayPublicKey | 采用公钥模式时填写微信支付公钥；不能填商户私钥或商户公钥 |
| wxPayPublicKeyId | 与微信支付公钥配套的 ID；成对配置 |
| signMode | 当前支持 sdk / gateway；先核实线上实际模式，再按通知策略配置 |
| transferNotifyUrl | 核实后的转账结果通知完整 HTTPS 地址，无查询参数 |
| notifyURLPayURL | 已验证的支付通知完整地址；新增市场订单须在服务端正确分流 |
| notifyURLRefundsURL | 已验证的退款通知完整地址 |

同时核验该商户号与此 AppID 的正式绑定关系，以及回收原物主 OpenID 属于此 AppID；分别填对两个标识不等于绑定关系有效。

如果线上使用受支持的平台证书验签模式，需核验其证书管理和转账响应验签，不为照抄本表强制切换公钥。商户私钥负责请求签名，微信支付公钥/平台证书负责微信响应及通知验签，APIv3 密钥负责通知解密。[接入参数](https://pay.wechatpay.cn/doc/v3/merchant/4013070756)、[微信支付公钥说明](https://pay.wechatpay.cn/doc/v3/merchant/4012153196)

模板 cloudbaserc.json 的 WX_APP_ID、MCH_ID、API_V3_KEY 等大写占位名是模板输入，部署后映射为左栏名称；直接在运行环境只填大写名不会被当前 config.js 读取。源码不自动加载 .env，不能只在电脑新建 .env 就认为云端已经生效。

当前代码默认 gateway，Dockerfile 默认 sdk，实际云端配置未核实。该开关还影响原支付与退款；不得仅为了转账随手切换。通知安全改造见主设计第 8 节。

## 4. 回调地址：现在只能确认路径

| 类型 | 当前存在的内部路由 | 实际完整地址 |
| --- | --- | --- |
| 支付通知 | /wx-pay/unifiedOrderTrigger | 待确认 |
| 退款通知 | /wx-pay/refundTrigger | 待确认 |
| 转账通知 | /wx-pay/transferTrigger | 待确认 |

SDK 直收通知的完整地址 = 实际 HTTPS 服务入口 + 实际挂载前缀 + 上表内部路由。挂载前缀可能为空，必须从部署配置核实，不能重复拼接 /wx-pay。入口有此路径不表示通知已经可信。

若线上是微信集成网关，使用网关为相应事件实际分配的地址，同时验证转账事件支持和来源认证；不能把 SDK 路径拼到网关域名上。当前转账业务钩子仍关闭。

三个概念分开填写：小程序调用云函数标识用于用户业务请求；接口 IP 用于后端出站名单；notify_url 用于微信异步通知。配置好其中一个不会自动完成另外两个。

## 5. 微信请求由服务端生成，不由用户填写

后续小程序只提交回收单ID和幂等请求ID。后端先验证该单已经验收、属于当前用户且还有可领取款项，再从保存的领取意图构造下列字段。

接口：POST https://api.mch.weixin.qq.com/v3/fund-app/mch-transfer/transfer-bills。[官方接口](https://pay.wechatpay.cn/doc/v3/merchant/4012716434)

| 请求字段 | 可信来源 |
| --- | --- |
| appid | 服务端 appId |
| out_bill_no | 服务端领取意图的固定商户转账单号，重试不临时换号 |
| transfer_scene_id | 服务端固定字符串 1010 |
| openid | 与该 AppID 一致的回收原物主身份绑定；不接受前端另填 |
| transfer_amount | 验收回收单净应付金额，整数分；不接受前端另填 |
| transfer_remark | 服务端根据真实回收业务生成 |
| notify_url | 服务端 transferNotifyUrl |
| transfer_scene_report_infos | 固定一条：info_type 为“回收商品名称”，info_content 为该回收单真实商品名称 |
| user_recv_perception | 可省略；如填写，二手回收场景使用“二手回收货款” |

二手回收商品报备内容按官方要求为 1–32 字符；上传时须有符合长度的真实商品名称，不能用领取备注、营销理由替代商品事实。本场景不使用红包样式。[二手回收参数](https://pay.wechatpay.cn/doc/v3/merchant/4013774592)

当前没有实现姓名加密，首版净款必须严格小于 200,000 分，并满足更低的正式获批额度；不接受 user_name。达到 2,000 元的转账需要按官方要求加密传入真实姓名，不能只提高后台金额限制就使用现有代码。该限制要从报价阶段校验，避免先形成应付款再发现接口无法处理。[姓名字段要求](https://pay.wechatpay.cn/doc/v3/merchant/4012716434)

查询原单：GET /v3/fund-app/mch-transfer/transfer-bills/out-bill-no/{out_bill_no}。由服务端读取当前用户对应领取单的单号查询，不提供任意商户单号公开查询。付款失败重试和未知结果处置按主设计，不能靠重新生成单号解决超时。
