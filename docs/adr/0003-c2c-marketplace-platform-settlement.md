# ADR-0003：校园个人闲置采用独立的 C2C 平台结算域

## 状态

Accepted（业务流程开发阶段；真实收款与转账默认关闭）

## 背景

校园闲置原本只提供信息发布和站内私聊。新的业务要求是买家在小程序付款，平台在交付完成后向个人卖家结算，并按公开规则收取服务费。这与现有“平台回收后转卖”的商品归属和付款方向不同。

## 决策

新增独立的 `c2c-market` 云函数和订单、账本、结算、争议、幂等集合；不复用回收款领取单，不把交易金额写入用户余额字段。首版是一件商品、一笔校内当面交付订单。

交易状态为：`pending_payment -> paid -> seller_delivered -> buyer_confirmed -> settlement_available -> payout_pending -> payout_success`。退款、争议和渠道未知状态会冻结结算，不允许卖家再次申请转账。金额、服务费和收款人均由服务端已锁定的订单快照推导。

支付回调与商家转账回调才可改变支付或到账终态。客户端只可创建订单、标记交付、确认收货、发起争议和申请结算；不能提交金额、费用、OpenID、转账场景或收款人。

真实 C2C 收款、商家转账和服务费扣款由服务端配置开关控制，默认关闭。启用前必须完成支付权限、转账实际场景、固定出口 IP、回调验签、正式费用规则和全量回归验证。

## 结果

### 正面

- 个人闲置、平台回收和代售点订单相互隔离，支付回调不会把资金写到错误业务。
- 订单、商品占用、账本和争议可按固定业务编号对账，异常时可冻结而不重复付款。
- 可先在测试环境完整验证业务状态，再开通真实资金动作。

### 负面

- 需要部署新的云函数、集合和索引，并补充买卖双方的订单页面。
- 未配置且公布有效服务费规则时，系统只能按零服务费生成结算快照。
- 商家转账开通本身不等于可将 C2C 买家款自动结算给个人卖家；实际场景和商户责任仍需微信支付侧确认。

## 备选方案

- **继续信息撮合**：风险小，但不满足客户提出的平台结算体验。
- **把 C2C 卖家当平台回收对象**：会错误表述商品归属和资金用途，未采用。
- **维护可编辑的用户钱包余额**：无法可靠处理回调、退款和并发提现，未采用。
