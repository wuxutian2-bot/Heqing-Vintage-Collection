# 系统头像库设计

## 目标

`avatars_extracted` 中的 214 张 PNG 作为鹏宇优选唯一的用户头像库。新用户首次登录随机获得一个头像；用户记录永久保存头像编号和云文件标识；用户可以在“我的”页面从同一头像库中主动更换。系统不读取微信头像。

## 资源策略

214 张头像原始大小约 3.72MB，而小程序单个主包上限为 2MB，因此头像不进入客户端主包。原图随 `login` 云函数部署到 `avatar-assets` 目录。云函数按需将头像发布到 `system-avatars/v1/` 云存储路径，并在 `avatar_assets` 集合中缓存 `avatarId -> fileID` 映射。

## 数据结构

- `users.avatarId`：1 至 214 的稳定系统头像编号。
- `users.avatarUrl`：对应云存储文件 ID。
- `users.avatarKey`：旧版 8 个 SVG 的兼容字段，新云函数未部署或迁移未完成时用作降级头像。
- `avatar_assets`：以 `avatar_001` 至 `avatar_214` 为文档 ID，保存系统头像编号、文件名、版本和文件 ID。

## 数据流

1. 登录云函数为没有 `avatarId` 的用户随机生成编号。
2. 若对应头像尚未发布，云函数从内置资源上传到云存储并缓存映射。
3. 登录响应返回同一 `avatarId` 和 `avatarUrl`，后续登录不会重新随机。
4. 个人页每次加载 24 个头像选项；选择后调用 `updateAvatar`，服务端只接受 1 至 214 的系统编号。
5. 商品、帖子、评论、收藏和私聊统一读取用户记录中的 `avatarUrl`。

## 状态与兼容

- 头像列表包含首次准备、分页加载、空状态和保存中状态。
- 旧用户打开“我的”页面时会自动刷新身份并迁移到系统头像库。
- 若云头像暂不可用，界面继续使用旧版本地 SVG，不影响登录和内容展示。

## 部署

创建私有 `avatar_assets` 集合，并重新部署 `login`、`posts`、`goods`、`comments`、`favorites`、`chat` 和 `maintenance` 云函数。首次命中某个头像时会自动上传，无需手工逐张导入云存储。
