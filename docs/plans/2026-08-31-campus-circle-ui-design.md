# 鹏宇优选校园圈 UI 与功能设计

## 1. 产品定位

校园圈不是第二个“大市场”，而是面向校内学生的生活情报与互助社区。页面优先解决四类高频需求：问同学、找搭子、寻失物、看新生指南；二手买卖继续留在独立的“市场”模块。

正式名称统一为“校园圈”。不使用学校官方徽标、虚构校友人数或未经确认的校园统计，避免用户误认为是校方官方平台。

## 2. 信息架构

首页由上至下分为六层：

1. 品牌头部：`鹏宇校园圈 / 同校可见 · 友善交流`，说明社区边界。
2. 搜索：在当前频道已加载内容中搜索标题、正文、频道和作者。
3. 快捷频道：求助、找搭子、失物、新生；点击后直接切换对应频道。
4. 今日热议：展示按浏览量排序的真实帖子，不写死虚假热榜数据。
5. 频道与排序：全部、校园动态、求助问答、拼单搭子、失物招领、新生指南、吐槽闲聊；支持最新和热议。
6. 动态信息流：作者头像与副名称、发布时间、频道、标题、摘要、最多三张预览图、浏览/评论/点赞数量和详情入口。

发布入口采用右下角固定按钮，不占用底部导航。频道快捷入口进入发布页时会自动预选对应频道。

## 3. 视觉规范

- 主色：森林绿 `#167A53`；深绿 `#173F31`；强调金 `#E5B96B`。
- 页面底色：冷灰绿 `#F3F6F4`；卡片白 `#FFFFFF`。
- 正文：`#173D30`；次级文字：`#81928B`；边线：`#EDF1EE`。
- 头部使用深绿品牌面，不做 AI 风格大渐变；内容区用浅底和克制阴影形成正式产品层级。
- 快捷频道用低饱和薄荷、奶油、浅蓝和浅粉区分，不使用卡通学校徽标。
- 关键点击区高度不低于约 80rpx；频道使用横向滚动，避免小屏文字被压缩。

## 4. 页面状态

- 加载：信息流骨架屏，不显示大段“加载中”。
- 空频道：说明当前频道暂无动态，并提供发布按钮。
- 搜索无结果：保留当前筛选条件，提供清空搜索操作。
- 列表到底：明确显示“没有更多动态了”。
- 热议加载失败：不阻断主信息流，自动隐藏热议内容或显示邀请文案。
- 发布中：按钮锁定并显示 loading，防止重复提交。
- 详情空状态：帖子不存在时显示独立空状态，评论为空时引导友善回复。

## 5. 数据与接口

帖子新增 `category` 字段，可选值固定为：

- 校园动态
- 求助问答
- 拼单搭子
- 失物招领
- 新生指南
- 吐槽闲聊

列表云函数接受 `category` 与 `sort`：`latest` 按 `createdAt` 倒序，`hot` 按 `viewCount` 倒序。未知分类统一回退为“校园动态”。旧帖子由维护函数补齐默认分类，前端在迁移前也会兼容显示。

前端在收到列表后会再次严格校验 `post.category === activeCategory`，并使用请求版本号丢弃快速切换频道时返回的旧请求，避免旧版云函数或异步请求造成分类串栏。云端筛选仍必须部署，它负责正确分页和减少传输量；前端过滤只作为展示安全兜底。

需要建立帖子复合索引：

- `category + createdAt`
- `category + viewCount`

全局热议还需要 `viewCount` 索引。索引配置已写入 `deployment/recommended-indexes.json`。

## 6. 隐私与社区边界

- 作者仅显示站内随机头像和 `鹏宇用户+编号`，不读取微信头像昵称。
- 发布页提示不要公开手机号、宿舍门牌等敏感信息。
- 私聊沿用现有站内会话，不引导添加私人微信。
- 标题、正文和图片继续通过云端内容安全检测。
- “同校可见”目前是产品文案；若以后开放多学校，列表接口必须增加并强制校验 `schoolId`。

## 7. 上线步骤

1. 部署 `posts` 云函数，使分类保存、筛选和热议排序生效。
2. 部署 `maintenance` 云函数，并执行一次幂等迁移，为旧帖子补齐分类和浏览量。
3. 按 `deployment/recommended-indexes.json` 创建帖子索引，等待索引构建完成。
4. 重新编译小程序，验证六个频道、最新/热议、搜索、发布预选分类、帖子详情、评论、点赞与私聊。
5. 真机检查 320px 与 390px 左右宽度、长标题、0/1/3/6 张图片、空列表和弱网状态。
