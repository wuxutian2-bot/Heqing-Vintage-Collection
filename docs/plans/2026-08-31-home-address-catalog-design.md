# 首页、默认地址与商品目录设计

## 目标与选择

首页作为小程序第一个页面和底部导航第一项，市场保持第二项。未登录用户进入首页时立即跳转登录；首次登录若没有默认地址，必须先完成楼栋、楼层和宿舍选择，再回到首页。地址按 `1–16号楼 / 1–6层 / 每层01–39宿舍` 建模，显示为“3号楼 512宿舍”。这里选择结构化字段而不是只保存一段文本，因为服务端需要校验楼栋范围、自动匹配对应代售点，并在结算时防止前端篡改配送地址。

首页采用参考图的零售布局：顶部是可点击的默认地址和搜索框，中部为左侧固定分类栏、右侧纵向商品列表，底部保留现有五栏导航。放弃“八宫格分类 + 双列卡片”，减少视线跳跃，更适合当前27个低价零食商品快速浏览。地址改变时首页自动切换到对应楼栋代售点；若购物车来自另一栋楼，保存新地址前提示并清空购物车。

## 数据与库存

用户文档新增 `defaultAddress`：`buildingNo`、`floorNo`、`roomIndex`、`roomNo`、`displayText`，同时维护 `selectedOutletId`。登录云函数继续返回公开用户资料，并新增经过严格整数范围校验的地址保存操作。

商品表共27项，采用表中的9个业务分类和售价（首页另加“全部”，因此分类栏共10项）。选择“每栋楼独立复制商品库存”，而不是全校共享库存或运行时读取 Excel：16栋楼各有一个固定代售点，每个商品使用稳定文档 ID 幂等创建。表格没有库存列时初始库存为1；已有商品不会在重复初始化时重置库存。订单创建仍在数据库事务中校验并预占库存，成功创建即扣减，取消或超时返还。

工作簿的“分类汇总”页写的是25件，且漏算“美思缘辣条”和“香肠类”；实现以“商品分类”明细页的27条有效商品为准，不采用错误汇总数。

## 结算、安全与兼容

结算页不再让用户临时填写房间号，只展示账户默认地址，手机号和备注继续按订单填写。创建订单时后端只读取 `users.defaultAddress`，并校验地址楼栋与代售点 `buildingNo` 一致，前端传入的房间号不再可信。旧用户登录后如果没有结构化地址，会进入首次设置流程；旧代售点和管理员商品仍保留。商品目录初始化仅管理员可调用，并返回创建/跳过数量，支持中断后重复执行。

验收覆盖：首次登录强制地址、地址永久保存、修改地址、跨楼购物车、27个商品/9个业务分类、16栋楼独立库存、库存扣减与返还、默认首页顺序、结算地址不可篡改，以及旧用户兼容。
