# 校园圈身份、私聊与管理员治理设计

## 目标与根因

线上截图显示 `chat` 云函数未部署；同时线上 `posts`、`comments` 仍未返回新版作者信息和浏览数行为。小程序前端不能单独修复云端缺失，因此本次交付同时包含代码修复、旧数据迁移与明确的云函数部署清单。

## 作者身份与浏览量

新商品、帖子和评论在创建时保存作者用户 ID、系统副名称、头像编号及头像文件地址的快照。读取时优先关联 `users` 中的最新资料，关联失败时回退到快照，以避免历史内容出现空头像、空副名称和无法私聊。维护函数按 `_openid` 为旧商品、帖子和评论补齐快照。

帖子详情每次由页面首次加载调用一次 `detail`，云函数先原子增加 `viewCount` 再读取并返回新值；刷新评论时显式传 `countView: false`，避免一次进入因评论刷新重复计数。商品详情继续采用相同规则。

## 私聊

私聊仅允许登录用户从有效商品或帖子详情发起，目标用户必须与内容作者匹配且属于同一学校。会话、消息、屏蔽和举报数据全部经过 `chat` 云函数鉴权，客户端无数据库直读权限。`chat` 首次运行会尝试初始化所需集合，但正式上线仍应在控制台确认集合与索引存在。

## 管理员权限

权限统一存放在 `users.role`。普通用户为 `user`，管理员为 `admin`。不提供任何客户端“申请管理员”或“修改角色”接口；开发者只能在微信云开发数据库中按用户副名称找到用户文档并手工将 `role` 改为 `admin`。用户重新登录后客户端才显示管理按钮。

所有管理操作必须在云函数重新读取调用者 OpenID 对应的用户文档并检查 `role === "admin"`：

- 市场：管理员可将任意在售商品设为 `removed`。
- 校园圈：管理员可置顶、取消置顶或删除任意帖子。
- 评论：管理员可删除任意主评论或回复；删除主评论时连同其回复和点赞记录清理，并重新计算帖子评论数。

帖子作者仍可删除自己的帖子，评论作者仍可删除自己的评论，但不能使用置顶或跨用户治理能力。

## 验收

1. 新旧帖子和评论均展示“鹏宇用户XXXX”及系统头像，作者用户 ID 可用于发起私聊。
2. 每次新进入帖子详情浏览数增加 1，评论刷新不重复增加。
3. 普通用户调用管理动作返回“无管理员权限”，即使伪造前端参数也无法越权。
4. 管理员可完成商品下架、帖子置顶/删除和评论删除，列表返回后立即反映结果。
5. 部署 `chat` 后，从帖子或商品发起会话、发送消息、消息列表与未读数正常。
