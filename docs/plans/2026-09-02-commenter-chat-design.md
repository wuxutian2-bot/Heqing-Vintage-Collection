# 评论区用户私聊设计

## 目标

在帖子详情的主评论和回复中补齐私聊入口。其他用户的头像、昵称以及操作栏“私聊”均可发起站内会话；自己的评论不显示“私聊”，游客先进入登录页。现有回复、点赞、管理员删除功能保持不变。

## 数据与安全

前端把评论记录的 `userId` 与 `_id` 分别作为目标用户和来源评论传给 `chat` 云函数，使用 `sourceType: "comment"`。云函数读取该评论后，再用 `userId` 或旧数据中的 `_openid` 核验目标用户确实是评论发布者；不接受仅凭客户端传入的用户 ID 建立会话。评论来源写入会话上下文，消息页可显示“评论：……”作为沟通来源。

## 交互

头像和昵称采用同一处理函数，操作栏增加带消息图标的“私聊”入口，提高可发现性。点击自己时提示“不能和自己发起私聊”；评论用户信息缺失时提示暂不可用；重复点击期间锁定请求，成功后进入现有聊天页。登录返回帖子详情时同步当前用户身份，正确隐藏自己的私聊入口。

## 验收

- 主评论和回复均能从头像、昵称或“私聊”进入对应用户会话。
- 自己的评论不显示私聊入口，云端仍拒绝自聊。
- 云端拒绝评论与目标用户不匹配的伪造请求，并兼容只有 `_openid` 的旧评论。
- 评论回复、点赞、删除以及帖子作者私聊不受影响。
- 云函数语法、WXML结构和回归测试通过。
