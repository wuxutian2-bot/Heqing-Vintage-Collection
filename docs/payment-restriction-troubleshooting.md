# 2026-09-04 小程序付款受限排查与修复

## 结论与边界

9 月 3 日截图明确出现“由于小程序违规，支付功能暂时无法使用”，说明至少该次付款触发了微信侧的小程序支付限制。9 月 4 日截图中的“暂时无法支付／请稍后重试”来自本地订单详情页的通用错误弹窗，本身不能区分平台限制、网络、签名或业务订单错误。

星期二能支付证明当时那笔交易成功，不代表之后的小程序权限、合规状态、运行版本或账号条件完全相同。本次不能仅凭截图确定处置发生时间或具体违规项。

已修复本地错误信息丢失、查单失败误报和微信订单详情动态路径兼容；**未部署此次云函数修复，未发布线上版本，未读取线上日志，未解除微信限制，也未发起真实付款、退款或发货操作**。

## 管理员现在要核对的内容

1. 登录**微信公众平台的小程序账号**，进入通知中心，查 9 月 1 日至 9 月 4 日与支付权限、违规、服务类目或订单管理有关的消息。记录具体限制原因、处置时间、整改事项及申诉入口。商户平台余额或提现成功不能证明小程序支付权限正常。
2. 在后台“支付与交易”相关菜单内找到“订单管理／订单发货管理／订单信息录入”（以当前界面名称为准），确认是否已接入，是否存在接入失败、待审核或待整改提示，并核对订单详情页配置。
3. 检查实际经营内容与已获准的服务类目是否一致。不要为了绕过限制选择不真实的类目或更换收款渠道。
4. 如通知指向商户权限、绑定或其他经营资料问题，再按对应通知检查商户平台及小程序的商户关联；不要无依据地重置 APIv3 密钥、私钥和证书。
5. 按通知要求真实整改并申请复核。解除时间以官方处理结果为准，不能承诺“等待 24 小时即可恢复”。

### 后续截图发现：订单详情路径字段为空

用户后续提供的通知中心列表没有显示明确支付违规消息；“订单信息录入”截图显示路径选择及输入框为空。页面说明要求路径包含 `${商品订单号}`，并明确将它替换为支付预下单的 `out_trade_no`。这是当前发现的具体接入缺口，但不能据此断定是唯一受限原因。

本地兼容修复部署后应录入完整模板：

```text
pages/order-detail/index?id=${商品订单号}
```

`${商品订单号}` 要原样保留，不要替换成某一笔固定订单号，也不要填写真实文档 ID。后台只支持一条路径，以页面验证/审核结果为准。部署和验证顺序见本文末尾。

微信支付官方明确建议对 `requestPayment:fail banned`、`access denied`、`no permission` 以及“小程序违规，无法使用支付”核对服务类目、交易规范、订单发货管理与通知中心，并按通知申诉：

- [小程序支付常见问题](https://pay.wechatpay.cn/doc/v3/merchant/4012791910)
- [小程序支付开发接入准备](https://pay.wechatpay.cn/doc/v3/merchant/4015459512)

以上公开资料于 2026-09-04 核对；本账号的具体限制原因仍以后台通知为准。

## 本项目的订单发货特别注意

- 小程序详情页读取参数 `id`。原实现只认 `orders` 集合的文档 `_id`，与微信动态模板传入的 `outTradeNo` 不同；页面显示的 `orderNo` 又是第三个字段。
- 2026-09-04 修复后，`orders` 云函数先匹配 `_id`，找不到时再精确匹配 `outTradeNo`，同时保留归属、状态、库存与金额校验。当前已发布客户端可继续将商户订单号作为 `id` 请求详情、准备支付或取消；更新后客户端会进一步回填真实文档 ID。
- 当前项目采用**手动录入微信发货信息**。管理员页面“已录微信发货”只在业务数据库标记 `shippingSyncStatus=manual_recorded`，**不会调用微信接口，也不等于已经向微信上传发货信息**。
- 对已实际履约的订单，先按真实履约方式在微信后台录入，再做本地确认；未发货订单不得虚假标记发货。自动发货同步需另行接入并验收。
- 这些是需重点核对的合规事项，当前没有证据证明它们就是这次封控的具体原因。

## 本地代码修复

修改 `miniprogram/utils/payment.js` 与 `miniprogram/pages/order-detail/index.js`：

- 兼容微信原生的 `errMsg` 和普通 `Error.message`，保留标量错误码与失败阶段。
- 微信明确返回限制提示时显示“微信支付受限”，其他错误保留其具体原因；不单凭数字 `errno=102` 或 HTTP 403 判断违规。
- 不再丢弃支付服务 HTTP 错误正文；能识别 HTTP 200 中包装的微信 SDK 失败响应，避免一律报“支付参数不完整”。
- 检查调起收银台所需参数是否缺失。
- 主动取消保持安静；商家取消等业务错误不能被误认为用户取消支付。
- 微信收银台成功返回但查单失败时显示“支付结果确认中”，不误报付款失败，不在客户端改订单为已支付。
- 诊断日志只记录阶段及标量错误码，不记录支付签名、完整支付响应、付款人资料或 Token。

失败阶段用于区分问题：

| 阶段 | 排查范围 |
| --- | --- |
| `preparePayment` | 业务订单、归属、状态、过期 |
| `wxpay_order` | 支付 HTTP 函数、业务钩子、微信统一下单返回 |
| `requestPayment` | 真机调起支付、微信权限、用户取消、支付参数 |
| `wxpay_query_order_by_out_trade_no` | 支付后查单；失败不等于未扣款 |
